## Accepted Risks (no action needed)

Documented decisions to live with known imperfections.

- **Settings resolver AppConfigService instance sharing (2026-05-05):** `compose-runtime.ts` creates a second `AppConfigServiceImpl` instance per installed app for the settings `appConfigResolver`, separate from the instance used by `CoreServices.config`. Both write to the same YAML files (currently correct behavior), but would silently desynchronize if `AppConfigServiceImpl` ever adds in-memory caching. Refactor: populate `appConfigByAppId` from the same instances the serviceFactory hands to each app. Prerequisite: expose app config service instances from the service factory.
- **D40** — `getActiveSpace()` fire-and-forget persist. Acceptable: self-healing on next request.
- **D42** — Conversation history anti-instruction framing removed. Accepted: continuity > theoretical injection risk.
- **Callback space semantics — originating scope** — Inline keyboard callbacks resolve space context at tap-time, not button-generation-time. Encoding the originating scope into every callback data string is a large change with low practical impact (buttons are tapped promptly). Accepted as designed.
- **P8a — Active-work protection is silent** — When `pendingEdits` or `PendingSessionControlStore` blocks an idle reset (`status: 'protected'`), no inactivity notice is sent to the user. The session remains active and the protection window expires naturally. Sending a notice in the protected case would be misleading (the session isn't ending) and adds undesirable noise. Accepted by design.
- **Regression GUI run registry is in-memory only (2026-05-11)** — A `pnpm dev` restart while a regression run is mid-flight kills the subprocess and drops the run state. Cached per-case results on disk survive (REQ-REG-010). Recovery is "rerun the suite from the GUI" — acceptable for an admin-only operator UI where in-flight runs are infrequent. Persistence would require a write-ahead-log of run state to disk; deferred indefinitely.
- **Regression GUI single-active-run serialization (2026-05-11)** — Only one regression run can execute at a time across the GUI surface. The second concurrent `POST /gui/regression/runs` receives 409 with `{activeRunId}` so the UI can attach to the existing SSE stream instead of erroring. Required because the `CostTracker` delta-based metering only produces accurate per-call cost under sequential dispatch. Lifting this would require either (a) per-call usage plumbing through `LLMService.complete()` so cost isn't delta-derived, or (b) a per-run cost-tracker instance. Accepted as designed.
- **Regression GUI estimator constants are approximations (2026-05-11)** — `core/src/gui/services/regression/estimator.ts` ships hard-coded `$/case` constants per bucket (routing 0.005, receipt 0.06, chatbot 0.04, recall 0.01). These approximate observed costs but do not call into the production `CostTracker.estimateCost` calculator. Real safety is the per-run cap (`regression.maxRunBudgetUsd`, default $5.00). Replace when LLMService usage plumbing lands — see "B.2 carry-forward — LLMService.complete usage plumbing" below.
- ~~**Local Gemma 4 e4b is unreliable on session-control "continue" nuance**~~ — Removed 2026-05-12 (Codex P2 correction). Stale: fresh routing cache shows session-control is now 3/3 pass after the Batch 3 prefilter + few-shot examples landed. If the failure recurs under different inputs, re-open with new cache evidence.
- **Regression GUI v2 — pre-rework cache entries not in leaderboard (2026-05-13)** — Pre-this-phase cache entries lack the new `RunManifest` files (and the `evaluatedTier` field on `RunResult`). They do not appear in the Overview leaderboard or Trends charts. They remain fully accessible in the Compare tab. Operators can repopulate by re-running affected models. Accepted breaking change for the new surface.
- **Regression GUI v2 — Trends `<table>` fallback test is structural only (2026-05-13)** — REQ-REG-GUI-V2-016's accessible `<table>` fallback is asserted via the trends-partial smoke test (`?view=trends` renders without error). A targeted DOM-assertion test for the fallback's contents is deferred — the Trends partial only renders the table when `trendsHasData === true` and the route-test fixture doesn't currently inject a populated `runHistoryStore`. Manual verification covers this surface.

- **Regression GUI v2 — interactive charts (2026-05-13)** — Trends SVGs are static. Tooltips, zoom, click-to-filter all deferred. Adding interactivity means either vendoring a chart library (50–200KB JS) or hand-rolling SVG event handlers. Decide when there's specific user demand.

- **Regression GUI Polish — SSE event log + in-flight runs are in-memory (2026-05-13)** — The per-run event log added for SSE reconnect (`MAX_EVENT_LOG_ENTRIES = 1000` ring buffer, REQ-REG-GUI-V2-022) lives in the run registry. - **Regression GUI Polish — client wrapper not unit-tested with DOM (2026-05-13)** — The new EventSource wrapper in `regression-live.eta` (auto-reconnect with `Last-Event-ID`, 3-strike "Lost connection" banner, `gap`-event reload, terminal-state guard) is verified via (a) rendered-page assertions in `regression-routes.test.ts` (REQ-REG-GUI-V2-021/024 wiring is present in the response body), and (b) server-side SSE replay/gap tests. A DOM-level unit test with a fake `EventSource` was scoped but deferred — the `@pas/core` vitest config is node-only (no jsdom), so adding it would require new dependencies. Manual smoke (browser devtools "Offline" toggle) covers the gap.
- **Receipt parser — single-shot continuation cap (2026-05-15, PR1)** — On `finishReason === 'length'`, `parseReceiptFromPhoto` fires exactly one continuation call and never more. Receipts long enough to need a third pass (~160+ items, rare at Sam's Club / large bulk runs) surface `continuation_unresolved + output_truncated` on the final result and the user sees the "couldn't fully verify" Telegram warning. Operator action: verify manually or re-photograph in two halves. Lifting the cap to N-pass continuation would require state-machine plumbing and a budget guard; deferred until real-world need.
- **Chunk A.2 — synthetic expired-90d receipt is pristine OCR text (2026-05-15)** — `regression/fixtures/receipts/expired-90d.jpg` is rendered text on a white background, not a creased thermal print with faded ink and photo glare. A parser that passes this fixture cleanly may still fail on a real >90-day receipt with crumpled paper. Mitigation: the 4 real-receipt fixtures (costco-long, trader-joes-{correction,long,short}) exercise OCR robustness for in-window receipts; the synthetic fixture only proves the `isValidReceiptDate` rejection branch + `rawExtractedDate` preservation. Replacing with a real photographed expired receipt would strengthen coverage but is low priority — the date-rejection path is deterministic and has dedicated unit-test coverage.
- **Chunk A.2 — cropped Trader Joe's fixtures (2026-05-15)** — `trader-joes-long.jpg` and `trader-joes-short.jpg` are cropped above the printed date line in the operator's view of the photo. Sidecars omit `date` so the parser's actual extraction (whatever it reads from the full-resolution JPG) is accepted without assertion. If the parser ever silently falls back to today's date for these (e.g., because of an OCR regression that breaks date reading on full-resolution JPGs), this fixture pair would not catch it. Mitigation: the expired-90d fixture is the canonical date-fallback prober; the cropped fixtures aren't expected to exercise that branch.
- ~~**Receipt parser — cannot detect self-consistent inflation**~~ ✓ Two-oracle defense in regression suite (PR2, 2026-05-15). When the LLM fudges `unitPrice` AND `totalPrice` AND `subtotal` self-consistently, every PARSER-side check still passes — the parser cannot self-detect this failure mode. **The regression suite now defends with TWO independent oracles**: (1) `structural` over `.expected.json` (already catches the bug — see `regression/src/__tests__/structural-catches-inflation.characterization.test.ts`); (2) `transcription` over operator-authored `.transcription.yaml` ground truth (Codex review #1: structural alone is sufficient for the bug shape; PR2's value is drift resistance — preventing silent `.expected.json` regeneration — plus confidence tiers). Coverage: 4 real-receipt fixtures with both sidecars; 15 adversarial-persona integration scenarios. See REQ-FOOD-RECEIPT-TRANSCRIPTION-001..011.
- **LLM stack — Ollama `done_reason` heuristic on older SDKs (2026-05-15, PR1)** — Newer Ollama exposes `response.done_reason` (mapped to `finishReason`). Older versions don't, and the fallback is `eval_count >= options.maxTokens ? 'length' : 'stop'`. This can yield a false `'length'` when the model happened to stop exactly at the cap on its own. The receipt parser's continuation pass transparently resolves this — if there's nothing more to extract, the continuation returns `{lineItems: []}` and the final result is clean. Accepted as a known false-positive that costs one extra LLM call.

## Persona Regression Suite — Chunk B.2 carry-forwards (2026-05-11)

- **LLMService.complete usage plumbing** — `core/src/services/llm/index.ts:56–75` `LLMServiceImpl.complete()` returns only the response `string`, dropping the `usage` object even though `provider.completeWithUsage()` returns `LLMCompletionResult` with `{inputTokens, outputTokens}`.
